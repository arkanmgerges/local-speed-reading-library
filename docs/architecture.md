# Architecture

## Responsibilities

| Component | Owns | Never contains |
|---|---|---|
| **This repository** (`local-speed-reading-library`) | metadata, rights and provenance records, schemas, Dart tooling, CI, docs, the generated catalogue | book assets (`build/` is gitignored), secrets |
| **Cloudflare R2** bucket `lsr-books`, custom domain `books.localspeedreading.com` | production catalogue and immutable book assets | anything not generated by the pipeline |
| **The app** (`localspeedreading`, Flutter) | catalogue client, download, verification, install, offline reading | credentials, bundled catalogue copies |
| **The website** (`local-speed-reading-site`) | website, privacy policy, Play verification, a `/library` information page | book content or catalogue files |

```
source providers ─▶ this repo (metadata + tools) ─▶ GitHub Actions ─▶ R2 ─▶ books.localspeedreading.com ─▶ app
```

## Runtime flow in the app

1. `GET https://books.localspeedreading.com/catalog/catalog.json` (a few KB, cached with ETag).
2. When the user opens a language: `GET catalog/languages/<lang>.json` (about 1 KB per book).
3. When the user taps **Download** on one book: `GET <baseUrl><asset.path>` for that one
   asset only, then size check → SHA-256 of the compressed bytes → gunzip → SHA-256 of the
   content → JSON schema/version check → install. Nothing else is fetched.
4. An installed book is an ordinary local document; reading it never touches the network.

Every relative path in the catalogue resolves against `assets.baseUrl`, so the CDN can be
replaced without changing the book model.

## Identifiers

| Id | Form | Example |
|---|---|---|
| `workId` | `<author-surname>-<original-title-slug>`, `[a-z0-9-]` | `dostoevsky-crime-and-punishment` |
| `editionId` | `<workId>.<lang>.<edition-slug>`, `[a-z0-9.-]`, language lower-cased | `dostoevsky-crime-and-punishment.ro.1924-ionescu` |
| `assetVersion` | positive integer, monotonic per edition | `1`, `2` |
| asset path | `books/<lang>/<editionId>/v<N>/book.json.gz` | `books/ro/creanga-amintiri-din-copilarie.ro.wikisource/v1/book.json.gz` |

A *work* is the abstract text (Crime and Punishment). An *edition* is one concrete text in one
language: the original, or one specific translation, which is a separately copyrightable work.
An *asset* is our normalised rendering of an edition at one version. Rights are recorded per
edition because the translator matters as much as the author.

## Domain model (`schemas/book-metadata.schema.json`)

* **work**: `workId`, `originalTitle`, `originalLanguage`, `author {name, birthYear, deathYear}`, `originalPublicationYear`, `wikidata`.
* **edition**: `editionId`, `language` (BCP 47), `title`, `kind` (`original` | `translation`), `translator {name, deathYear}`, `editionPublicationYear`, `translationPublicationYear`.
* **source**: `provider`, `url`, `identifier`, `format`, `site`, `revision`, `pages [{title, revision}]`, `retrievedAt`.
* **rights**: `status` (`public-domain` | `uncertain` | `restricted`), `basis[]`, `jurisdictions[]`, `statement`, `evidence[]`, `verifiedBy`, `verifiedAt`.
* **genres**: from the app's canonical list (Fiction, Non-fiction, History, Science, Philosophy, Biography, Poetry, Children, Article, Other).
* **publish**: `assetVersion` (edited by hand when the text must change).
* **import**: optional per-edition normalisation hints (`chapterHeadingLevels`, `skipHeadings`, `removeSelectors`, `dropParagraphsMatching`, `firstChapterTitle`).
* **asset**: written by `lsr build`: `assetVersion`, `path`, `sizeBytes`, `sha256`, `uncompressedSizeBytes`, `contentSha256`, `wordCount`, `chapterCount`, `normalizerVersion`, `builtAt`.

## Normalized book (`schemas/normalized-book.schema.json`)

What the app downloads: plain Unicode text in ordered chapters, plus provenance and rights.

```json
{ "schemaVersion": 1, "workId": "…", "editionId": "…", "assetVersion": 1,
  "language": "ro", "direction": "ltr", "title": "…", "author": "…", "translator": null,
  "chapters": [ { "index": 0, "title": "I", "paragraphs": ["…", "…"] } ],
  "provenance": { "provider": "wikisource", "url": "…", "identifier": "…", "revision": "106333",
                  "pages": [ { "title": "…", "revision": 106333 } ], "retrievedAt": "…" },
  "rights": { "status": "public-domain", "statement": "…" },
  "normalizer": { "name": "lsr-library-tools", "version": "0.1.0" } }
```

Kept: chapter order and titles, paragraphs, verse line breaks inside a paragraph, Unicode in
NFC, right-to-left text untouched (direction marks and joiners preserved). Dropped: markup,
CSS, fonts, images, footnotes, tables of contents, licence boilerplate, page numbers. No
tokenisation: the app's reader splits on whitespace itself, and other engines can do their
own segmentation from the same text.

The pipeline converts the JSON to canonical form (sorted keys, two-space indent, `\n`,
trailing newline) before hashing and compression, so the same source at the same revision
gives the same bytes on every machine.

## Compression: gzip, not zstd

| Criterion | gzip | zstd |
|---|---|---|
| Reliable Android support | `dart:io` `GZipCodec`, built into every Flutter build | needs an FFI plugin; the pub packages are immature or lack Android binaries |
| Implementation | one line to decode | native library per ABI, plugin maintenance |
| Size on UTF-8 prose | ~35 % of raw (measured on the pilot: 0.25–0.37) | ~10–15 % smaller than gzip |
| Decompression speed | milliseconds for a 500 KB book | faster, irrelevant at this size |
| Debuggability | every OS has `gunzip`; browsers decode it natively | extra tooling |

Books are 40–220 KB compressed; the zstd saving would be tens of kilobytes per download.
Decision: **gzip**, object name `book.json.gz`, `Content-Type: application/gzip`,
`Content-Encoding` unset (the client decodes explicitly and verifies the compressed bytes).

The tool writes gzip with a fixed header (mtime 0, no file name, OS "unknown") over the
pure-Dart deflate so the compressed bytes, and therefore `sha256`, are reproducible.

## Two checksums

* `sha256` — of the compressed object. The app verifies it before decompressing anything.
  This rejects truncated, corrupt or substituted downloads.
* `contentSha256` — of the canonical JSON. CI uses it to prove that a rebuild of an already
  published version reproduces the same content (immutability); the app verifies it after
  decompression as a cheap second check.

`uncompressedSizeBytes` lets the client bound memory before decompressing.

## Catalogue (`schemas/catalog.schema.json`, `schemas/language-manifest.schema.json`)

* `catalog/catalog.json`: schema version, `catalogVersion` (content hash), `assets.baseUrl`,
  one entry per language with names, direction, `bookCount`, `manifest` path,
  `manifestVersion` and `manifestSha256`.
* `catalog/languages/<lang>.json`: `books[]` with work/edition metadata, genres, the rights
  statement, the source pointer and the **current** asset record. No text.

Versions are content hashes rather than timestamps so that regenerating an unchanged
catalogue is a no-op and `lsr catalog --check` can compare bytes in CI.

## Immutability and versioning

* `books/<lang>/<editionId>/v<N>/book.json.gz` is written once and never overwritten.
  `lsr publish-check` downloads any existing copy and fails when its SHA-256 differs.
* Changing the text means bumping `publish.assetVersion` and rebuilding: a new object, a
  new manifest entry, old objects left in place. A client holding a stale manifest still
  downloads successfully.
* Updating one book changes one manifest and the catalogue; no other asset changes.
* The metadata file records the provider revision (`source.pages[].revision` for Wikisource,
  `Last-Modified` for Gutenberg) so a rebuild fetches the same text. If the provider changed
  the text under the same pin, `lsr build` reports content drift and refuses to rewrite an
  existing version.

## Caching

| Object | Cache-Control | Why |
|---|---|---|
| `catalog/catalog.json` | `public, max-age=300, must-revalidate` | new languages/books show up within minutes |
| `catalog/languages/*.json` | `public, max-age=900, must-revalidate` | same, per language |
| `books/**` | `public, max-age=31536000, immutable` | versioned paths never change |

The app sends `If-None-Match` with the stored ETag for catalogue files and keeps the last
valid copy when the network or the CDN is unavailable. Query strings are not needed and are
ignored by the cache rule (see [cloudflare-r2.md](cloudflare-r2.md)).

## Languages

Language tags are BCP 47 (`en`, `ro`, `pt-BR`, `zh-Hans`, `sr-Latn`). `sources/languages.json`
lists the tags the app can label and lays out their text direction; it is a copy of the app's
`tool/languages.json` and the two must stay in sync. Inside identifiers and object paths the
tag is lower-cased (`pt-br`); the manifest carries the canonical form.

Nothing in the pipeline assumes Latin script, left-to-right order, whitespace word
boundaries or ASCII punctuation. Word counts are whitespace-based because that is how the
app's reader currently tokenises; languages written without spaces will need engine work
before they are added to the catalogue.

## Tooling

`tools/` is a plain Dart package (`dart run bin/lsr.dart …`), the same toolchain as the app.

| Command | Does |
|---|---|
| `pin` | resolves the provider's current revision(s) and writes them into `source` |
| `build` | fetches the pinned source (snapshot in `build/sources/`), normalises, packages, writes `build/books/…` and the `asset` block; `--offline` reuses the snapshot, `--check` fails instead of writing, `--allow-rewrite` accepts changed content for a version that was never uploaded |
| `validate` | schemas, ids, languages, sources, rights policy, asset blocks vs `build/`, catalogue freshness and references |
| `catalog` | regenerates `catalog/`; `--check` compares with the committed files |
| `show` | chapter outline of a built book, for review |
| `publish-check` | HEAD/GET against the CDN: missing, identical, different (fatal), unreachable; `--plan` writes the upload list |
